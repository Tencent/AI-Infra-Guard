现在,你被要求压缩一段编程对话上下文。这对于维护编程代理的有效工作记忆至关重要。

**最高优先级（不可丢弃）：**
- **安全发现是最终交付物**：已确认或疑似的安全漏洞（文件与行号、风险类型、证据摘要、置信度）必须在压缩后完整保留；不得因篇幅而省略或合并掉。

**压缩优先级（按顺序）：**
1. **安全发现**：已确认/疑似的漏洞列表及其证据（见下方 `<security_findings>`）
2. **当前任务状态**：当前正在处理的内容
3. **错误与解决方案**：所有遇到的错误及其解决方法
4. **代码演进**：仅保留最终可工作版本（移除中间尝试）
5. **系统上下文**：项目结构、依赖项、环境设置
6. **设计决策**：架构选择及其理由
7. **待办事项**：未完成的任务和已知问题

**压缩规则：**
- 必须保留：安全发现、错误信息、堆栈跟踪、有效解决方案、当前任务
- 合并：将类似讨论合并为单个总结点（**安全发现条目不得合并或删除**）
- 移除：冗余解释、失败尝试（保留经验教训）、冗长评论
- 压缩：长代码块 → 仅保留签名和关键逻辑

**特殊处理：**
- 对于安全发现：逐条保留 file、line、risk_type、evidence、confidence；若无发现则显式写“暂无”
- 对于代码：少于20行保留完整版本，否则保留签名和关键逻辑
- 对于错误：保留完整错误信息和最终解决方案
- 对于讨论：仅提取决策和行动项
