# AI API 中转站检测常见问题

> 检测结果仅代表技术风险信号，不能单独作为法律或商业纠纷依据。

## 1. 为什么要检测中转站是否使用假模型？

模型替换可能造成多付费用、能力下降、安全策略变化、接口不兼容及数据合规风险，还会导致线上效果、离线评测与供应商承诺不一致。检测可发现静默降级、动态换模和路由掺假，为采购验收、持续巡检与争议复测提供可重复的技术证据。

## 2. 可以检测哪些中转站风险？

可检测模型列表或身份不符、隐藏提示词注入、输出与工具命令改写、SSE 流损坏、上下文截断、Claude Signature 异常及统计指纹不符，并提供 Token、缓存、延迟和生成速度等辅助信号。系统采用多探针交叉验证，降低依赖单一自报字段造成的误判。

## 3. quick 模式怎么检测？

quick 是纯黑盒检测，不读取中转站代码或内部配置。它依次执行模型列表、精确回显、身份自报、Token 偏差、命令回显、SSE 完整性和长上下文 canary 共 7 个探针，检测模型缺失、内容改写、隐藏注入、流损坏、model 字段不符及上下文截断。探针使用随机化标记，并按适用性和证据充分性过滤结果，再以风险权重计算安全分。

## 4. full 模式比 quick 多什么？

full 保留 quick 的全部黑盒检查，并增加 50～500 次指纹采样，默认 200 次。有效回答会转换为 355 维计数向量，通过 Dirichlet 平滑和 Dirichlet-Multinomial 后验预测与参考基准逐一比较，输出最高后验候选。若声明模型存在于基准库，系统还会结合已知替代模型的对数贝叶斯因子与 G² 异常值，区分支持声明、已知替身和未知异常。最高后验候选与声明模型一致且后验不低于 85% 时，单独的 G² 偏移按同模型分布漂移处理，不误报为模型替换。该方法提供可量化统计证据，但仍受版本、参数、动态路由和有效样本量影响。

## 5. Claude 模型会增加哪些检查？

系统先请求 extended thinking 采集 signature，解析 protobuf 封装、模型绑定与密文统计特征，再将 signature 回放给同一 API 验证处理能力。同时检查返回模型名、Anthropic 或 Bedrock 响应头、thinking_tokens、stop_reason、Token 统计、system prompt 弱信号和延迟。它把结构、回放与协议行为组成多层证据链；通过表示链路获得符合预期的 Claude 证据，不等于官方直连。

## 6. 模型指纹是怎么检测的？

模型在相同提示下并非真正均匀随机，不同训练、对齐和推理机制会形成相对稳定的数字选择偏好。系统重复采样并与参考分布比较，使用后验概率和 log margin 衡量候选模型的相对证据，再用贝叶斯因子识别已知替身、用 G² 检测参考库外异常。指纹属于群体统计证据，不能由单次回答证明，也不能等同于身份认证。

## 7. API Key 会写入日志吗？

结构化日志不会记录 API Key 原文，只保存最后 3 位和完整 SHA-256，用于在不暴露密钥的前提下关联同一 Key 的多次检测。原始 Key 仅在当前任务内存中用于请求上游；日志同时记录请求 ID、模型、目标地址、耗时、评分和判定，便于定位 429、502、超时及上游异常。
